# sthings-edge

Bare-metal edge box (LattePanda Mu, Intel N100, 8 GB, eMMC) for the table tennis setup
(Schmetterpause, Zählwerk, ESPs). It runs in two networks:

| Network | Router | Gateway | Role | Runs |
|---|---|---|---|---|
| Table tennis network | GL.iNet Opal (GL-SFT1200) | `192.168.8.1` | `tt` | k3s + Cilium + Flux, no browser |
| SthingsNet | dd-wrt | `192.168.10.1` | `kiosk` | Firefox kiosk, no k3s |

The role is detected from the default gateway by `/usr/local/bin/edge-role`
and can be overridden in `/etc/edge-role` (`auto` | `tt` | `kiosk` | `none`).

This README is the run book for this box, in build order. The general edge docs
(lab clusters, architecture, every option) live in [`docs/edge`](../../docs/edge/index.md).

## 1. Router (Opal, GL firmware 4.8.3 / OpenWrt 18.06)

| | |
|---|---|
| Uplink | INTERNET → Repeater → `SVA Visitor` (open, no password) |
| LAN | `192.168.8.0/24`, own Wi-Fi `sthings-edge`, DHCP `.100–.249` |
| Box | static lease MAC `00:e0:4c:0a:f6:ff` (`enp1s0`) → `192.168.8.10`, name `sthings-edge` |
| VIPs (outside DHCP) | `192.168.8.20` Gateway (`*.edge.sthings.lab`), `192.168.8.21` players (`sthings-edge.com`) |
| DNS | dnsmasq: `edge.sthings.lab` local, service names → `.20`, `sthings-edge.com` → `.21` |

The box needs the LAN port of the Opal, **not the WAN port** (on WAN it gets no `192.168.8.x`).
SthingsNet (dd-wrt) gets its own static lease for the same MAC; the host stays on DHCP.

**SSH as root.** Dropbear offers only `ssh-rsa`. Put the Mac's key on once (asks for the admin
password; run it in a normal terminal, a `!` prompt in Claude Code can't answer it):

```bash
cat ~/.ssh/id_rsa.pub | ssh -o HostKeyAlgorithms=+ssh-rsa root@192.168.8.1 \
  'cat >> /etc/dropbear/authorized_keys && chmod 600 /etc/dropbear/authorized_keys'
alias opal='ssh -o HostKeyAlgorithms=+ssh-rsa -o PubkeyAcceptedAlgorithms=+ssh-rsa root@192.168.8.1'
```

**dnsmasq** (applied 2026-10-12; backup `/etc/config/dhcp.bak-20261012` on the router;
background: [architecture.md](../../docs/edge/architecture.md), *DNS commands*):

```bash
uci set dhcp.@dnsmasq[0].domain='edge.sthings.lab'
uci set dhcp.@dnsmasq[0].local='/edge.sthings.lab/'
uci add_list dhcp.@dnsmasq[0].rebind_domain='edge.sthings.lab'
uci add_list dhcp.@dnsmasq[0].rebind_domain='sthings-edge.com'
for n in schmetterpause zaehlwerk buttons openbao minio minio-console led-catcher light-catcher \
         light-catcher-tabletennis wled-mock config-viewer demo-pitcher core-catcher omni-pitcher scout; do
  uci add_list dhcp.@dnsmasq[0].address="/$n.edge.sthings.lab/192.168.8.20"
done
uci add_list dhcp.@dnsmasq[0].address='/sthings-edge.com/192.168.8.21'
uci set dhcp.@host[0].name='sthings-edge'
uci commit dhcp && /etc/init.d/dnsmasq restart
```

- Concrete names, not `address=/edge.sthings.lab/…`: that would also catch the devices' names.
  A new HTTPRoute hostname needs its own `address` line (list them: [step 11](#11-use-and-verify)).
- GL DNS stays on `auto` (no "Override DNS Settings for All Clients"), so clients use dnsmasq.
- **Hetzner: nothing to change.** The public `*.sthings-edge.com` record stays on the lab's
  players' VIP; inside the Opal LAN the router answers it, and Let's Encrypt validates by DNS-01.

Check: `dig +short @192.168.8.1 zaehlwerk.edge.sthings.lab` → `192.168.8.20`,
`dig +short @192.168.8.1 schmetterpause.sthings-edge.com` → `192.168.8.21`.

## 7. Kiosk (role `kiosk`)

Needs `sthings-baseos-26.1011.1463` or later (stuttgart-things/ansible#1367: in `auto`
mode tty1 waits up to `edge_role_wait_seconds` for a default route; `26.1011.1459` lacks this).

```bash
ansible-playbook -i inventory sthings.baseos.kiosk -e target_host=edge \
  -e kiosk_url=https://<start-page>
```

Several pages, one tab each, optionally switching to the next tab every N seconds
(stuttgart-things/ansible#1370, not released yet; tested on the box from the PR branch):

```bash
ansible-playbook -i inventory sthings.baseos.kiosk -e target_host=edge \
  -e kiosk_urls=https://<page-1>,https://<page-2> -e kiosk_rotate_seconds=30
```

How it works:

- `getty@tty1` runs `/usr/local/bin/tty1-getty`, which autologins user `kiosk`
  only in role `kiosk` (re-evaluated on every respawn), otherwise shows a normal login.
- `~kiosk/.bash_profile` execs `cage` with `/usr/local/bin/kiosk-session`, which starts
  Firefox (`.deb` from packages.mozilla.org) with one tab per URL. With rotation on, a loop
  sends `xdotool key ctrl+Tab`. When Firefox exits, the session ends and getty logs in again.
- Without rotation, switch tabs with Ctrl+Tab on a keyboard (there is no tab bar in kiosk mode).
- Logs: `journalctl -t kiosk -b`

Test in the table tennis network:

```bash
echo kiosk | sudo tee /etc/edge-role && sudo systemctl restart getty@tty1
# Ctrl+Alt+F2 = console, Ctrl+Alt+F1 = kiosk
echo auto | sudo tee /etc/edge-role && sudo systemctl restart getty@tty1
```

Known issues / decisions:

- **Monitor must be connected** (`cat /sys/class/drm/*/status` shows `connected`), otherwise cage aborts.
- **Firefox runs via Xwayland** (`MOZ_ENABLE_WAYLAND=0`): native Wayland triggers
  `wlr_xdg_surface_schedule_configure: Assertion 'surface->initialized' failed` in cage 0.2.1.
  This is also why `xdotool` (XTEST) can drive the tab rotation.
- A plain systemd service (`PAMName=login`) did not get `seat0` from logind → replaced by tty1 autologin.
- Harmless log lines:
  - `Sandbox: CanCreateUserNamespace() … EPERM`: Ubuntu's AppArmor profile `firefox` covers `/usr/lib/firefox/firefox`.
  - `[xwayland ei] EI setup failed`: XTEST works without libei.
  - `xkbcomp` keycode warnings.

## 8. k3s + Cilium (role `tt`)

Run book and results: [`k3s/README.md`](./k3s/README.md). k3s 1.35.9 on sqlite, Cilium 1.20.2,
Gateway API v1.6.1 -- the same stack as the lab node `edge-tt-test1` ([`../edge/k3s`](../edge/k3s/README.md)).

```bash
ansible -i k3s/inventory.ini all -b -m shell -a 'edge-role show'     # must print tt
ANSIBLE_BECOME_ASK_PASS=False ansible-playbook -i k3s/inventory.ini sthings.rke.k3s_cluster -e @k3s/k3s-vars.yaml
mkdir -p -m 700 ~/.kube && install -m 600 /tmp/kubeconfig-sthings-edge.yaml ~/.kube/sthings-edge && rm /tmp/kubeconfig-sthings-edge.yaml
```

- k3s only starts in role `tt`: `/etc/systemd/system/k3s.service.d/edge-role.conf`
  (`ExecCondition=/usr/local/bin/edge-role is tt`, installed by `sthings.baseos.kiosk`).
  Run the install in the table tennis network only. Verified by reboots: in `kiosk` the unit
  is skipped (`exec-condition`), in `tt` the node comes back Ready.
- The k3s run enables **UFW** (allow list from baseos/`configure_rke_node`, no 80/tcp). It does not
  touch the VIPs: Cilium handles their traffic in eBPF before UFW's INPUT rules, so
  `http://…edge.sthings.lab` (301 → https) works on `edge-gateway`'s port-80 listener.
- sthings.rke has no hook for k3s `node-ip` or Cilium `devices`. k3s picks `enp1s0` by itself
  (default route). L2 announcements go out on every interface until stuttgart-things/flux#678.

## 9. Flux

The lab's procedure ([runbook.md](../../docs/edge/runbook.md), steps 5–6 and *Moving to the
hardware*) with this folder. The box decrypts with **its own key** (`cluster-secrets/age.pub` =
`age1dpnxq7tt9fqj7avs0euv69c5jaj70z9t826dhmjy2ll6t93a9gcsm3fx2a`); everything it reads is also
encrypted for the master key. Run from the repo root, with the exports of step 4.

**a) Render.** The hand-written files are `cluster-apps.yaml`, `cluster-vars.yaml`, `infra/ca.yaml`,
`infra/ca/kustomization.yaml`, `play/`, `edge-root-ca.crt`, `.sourceignore`. Leave out
`--existing-secrets` on the very first render (it creates the box key); keep it on every later one,
or the box key and all secrets are made anew:

```bash
env -u SSH_AUTH_SOCK dagger call -m github.com/stuttgart-things/blueprints/flux@v3.11.0 \
  render-cluster-apps --cluster-apps clusters/sthings-edge/cluster-apps.yaml \
  --master-age-key env:SOPS_AGE_KEY --escrow-recipients "$(age-keygen -y $SOPS_AGE_KEY_FILE)" \
  --sops-ref-dir . --existing-secrets clusters/sthings-edge/cluster-secrets \
  export --path /tmp/sthings-edge-gen
cp -r /tmp/sthings-edge-gen/flux/. clusters/sthings-edge/ && rm -rf /tmp/sthings-edge-gen
```

**b) Hand-encrypted files for the box key.** `infra/ca/edge-ca.enc.yaml` is the lab's file with
the box key added (same plaintext):

```bash
sops -r -i --add-age "$(cat clusters/sthings-edge/cluster-secrets/age.pub)" clusters/sthings-edge/infra/ca/edge-ca.enc.yaml
```

Check before committing: no `AGE-SECRET-KEY` in the diff, every value in `*.enc.yaml` is `ENC[…]`
(an empty `TEAMS_WEBHOOK_URL` is fine).

**c) Merge to `main`.** The FluxInstance syncs `refs/heads/main`; a path that exists only on a
branch leaves `flux-system` at `path not found`.

**d) Bootstrap** -- with the **box** key. `--age-public-key` must be its public key
(`validateAgeKeyPair` refuses anything else). It commits `config.yaml` and `secrets.yaml` to `main`;
pull them and add the two `# pragma: allowlist secret` comments to `config.yaml` (`patch: |-`,
`pullSecret:`).

```bash
umask 077; BOXKEY=$(mktemp)
sops -d clusters/sthings-edge/cluster-secrets/sops-age.enc.yaml | yq '.stringData."age.agekey"' > $BOXKEY
SOPS_AGE_KEY=$(grep '^AGE-SECRET-KEY-1' $BOXKEY) \
AGE_PUB=$(cat clusters/sthings-edge/cluster-secrets/age.pub) \
GITHUB_USER=<github user> GITHUB_TOKEN=$(gh auth token) \
env -u SSH_AUTH_SOCK dagger call -m github.com/stuttgart-things/blueprints/flux@v3.11.0 \
  bootstrap \
  --kube-config file://$HOME/.kube/sthings-edge \
  --deploy-operator=true --commit-to-git=true \
  --repository stuttgart-things/harvester --destination-path "clusters/sthings-edge" \
  --git-username env:GITHUB_USER --git-password env:GITHUB_TOKEN --git-token env:GITHUB_TOKEN \
  --sops-age-key env:SOPS_AGE_KEY --age-public-key env:AGE_PUB \
  --render-secrets=true --apply-secrets=true --apply-config=true --encrypt-secrets=true \
  --helmfile-ref "git::https://github.com/stuttgart-things/helm.git@cicd/flux-operator.yaml.gotmpl" \
  --wait-for-reconciliation=true --progress plain
rm -P $BOXKEY
```

The kubeconfig is read inside the Dagger container, which reaches `192.168.8.10` directly. If
it does not (OrbStack just started), use a copy with `server: https://host.docker.internal:16443`
and `tls-server-name: localhost` through the SSH tunnel of step 11.

## 10. OpenBao + MinIO

OpenBao initialises **itself** on its first start (self-init userpass: `terraform`, `admin`) and
unseals with the static seal key. Then, as in the lab
([terraform/openbao](../edge/terraform/openbao/README.md), [terraform/minio](../edge/terraform/minio/README.md))
with `env/box`. The router is the DNS resolver (`acme_dns_resolver` `192.168.8.1:53` in
`env/box.auto.tfvars.json`). Run from the repo root:

```bash
umask 077; T=$(mktemp -d)
printf 'nameserver 192.168.8.1\n' > $T/resolv.conf

# OpenBao: pki mount, URLs, role devices, ACME
sops -d --extract '["stringData"]["OPENBAO_TERRAFORM_PASSWORD"]' secrets/edge/app-values.enc.yaml \
  | jq -Rs '{openbao_password: rtrimstr("\n")}' > $T/openbao.tfvars.json
env -u SSH_AUTH_SOCK dagger call -m github.com/stuttgart-things/dagger/terraform@v0.136.0 \
  execute --terraform-dir clusters/edge/terraform/openbao --operation apply --refuse-destroy \
  --extra-files clusters/sthings-edge/edge-root-ca.crt,clusters/edge/terraform/openbao/env/box.auto.tfvars.json \
  --secret-json-variables file://$T/openbao.tfvars.json \
  --kube-config file://$HOME/.kube/sthings-edge --resolv-conf $T/resolv.conf --progress plain

# the "(openbao)" intermediate: key inside OpenBao, CSR signed offline with the root;
# refuses if the mount already has an issuer
OPENBAO_ADDR=https://openbao.edge.sthings.lab clusters/edge/terraform/openbao/sign-intermediate.sh

# MinIO: bucket schmetterpause-cnpg, user + policy for the CNPG backups
sops -d --output-type json secrets/edge/app-values.enc.yaml \
  | jq '.stringData | {minio_user: .MINIO_ADMIN_USER, minio_password: .MINIO_ADMIN_PASSWORD, cnpg_secret_key: .MINIO_CNPG_PASSWORD}' \
  > $T/minio.tfvars.json
env -u SSH_AUTH_SOCK dagger call -m github.com/stuttgart-things/dagger/terraform@v0.136.0 \
  execute --terraform-dir clusters/edge/terraform/minio --operation apply --refuse-destroy \
  --extra-files clusters/sthings-edge/edge-root-ca.crt,clusters/edge/terraform/minio/env/box.auto.tfvars.json \
  --secret-json-variables file://$T/minio.tfvars.json \
  --kube-config file://$HOME/.kube/sthings-edge --resolv-conf $T/resolv.conf --progress plain

rm -rP $T
```

Then the first CNPG backup by hand (the scheduled one of a fresh rollout fails,
[notes.md](../../docs/edge/notes.md)):

```bash
cat <<'EOF' | kubectl apply -f -
apiVersion: postgresql.cnpg.io/v1
kind: Backup
metadata: {name: schmetterpause-db-manual, namespace: schmetterpause}
spec:
  cluster: {name: schmetterpause-db}
  method: plugin
  pluginConfiguration: {name: barman-cloud.cloudnative-pg.io}
EOF
kubectl -n schmetterpause get backup schmetterpause-db-manual          # completed
```

**Result 2026-10-12:** OpenBao terraform 5 added; intermediate "(openbao)" under the edge root,
valid until 2031; ACME directory `https://openbao.edge.sthings.lab/v1/pki/acme/directory` answers.
MinIO terraform 4 added. CNPG `ContinuousArchiving=True`, manual backup completed.

## Troubleshooting

| Symptom | Cause / fix |
|---|---|
| Box not on `192.168.8.10`, its MAC not in `arp -an` | cable in the Opal's WAN port -- use a LAN port |
| `kubectl`: `connect: no route to host`, `nc -z 192.168.8.10 6443` works | macOS Local Network privacy (step 4) -- allow the terminal or use the tunnel |
| `sops`: `no identity matched` with the right key | macOS sops looks in `~/Library/Application Support/sops/age/`; set `SOPS_AGE_KEY_FILE` |
| `ssh root@192.168.8.1`: `no matching host key type` | add `-o HostKeyAlgorithms=+ssh-rsa -o PubkeyAcceptedAlgorithms=+ssh-rsa` |
| `HelmRelease … status: 'Failed'`, `RetriesExceeded`, pod Running anyway | install timeout on a slow image pull (visitor Wi-Fi): `sudo flux --kubeconfig /etc/rancher/k3s/k3s.yaml reconcile helmrelease <name> -n <ns> --reset` (2026-10-12: `homerun2/redis-stack`) |
| bootstrap: `validateAgeKeyPair` ERROR | `--age-public-key` is not the public key of `--sops-age-key` (use the box's `age.pub`) |
| MinIO terraform: `cannot import bucket` | fixed in harvester#425 (the `import` block is gone; Terraform creates the bucket) |
| `sign-intermediate.sh`: `shred: command not found` | fixed in harvester#425 (falls back to `rm -P`); a failed run leaves an unused key in OpenBao, harmless; rerun |
| new hostname does not resolve | add an `address` line on the router (step 1) |
